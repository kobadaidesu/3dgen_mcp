# solid-glb：立体の物の写真から GLB を作る

数枚の写真と設定ファイル（JSON）から、単純な立体の GLB を作る道具です。形はプログラムが組み立て、AI（または人）は写真を見て設定ファイルを書き、できあがりを見比べます。

- 入力：上からの写真 1 枚（必須。真上でも斜め上からでもよい）と、横からの写真（高さを読むため、立っている紙の部品の色、見比べるため）
- 出力：`model.glb`、`compare.jpg`（写真とモデルを同じ向きで並べた画像）、`report.json`
- 単位はメートル、+Y が上、底が y = 0、正面が +Z

## 作れる形

| テンプレート | 向いている物 | 仕組み |
|---|---|---|
| `slab` | 台の上に層を積んだ形の物（箱、板、トレー、操作盤、本、ふたのある容器、紙皿の上に作った工作） | 上からの写真で輪郭をなぞり、層を積む。上面（と、写真に写っている側面）には上からの写真を貼る。丸い部品（ボタン、つまみ、ねじ）を上に載せ、紙の部品を立てる |

作れるもの：

- 上が平らな物（前の版と同じ）。
- **層ごとに違う輪郭**：紙皿の上の箱のように、層ごとに輪郭をなぞれます。
- **上がすぼまった形・丸みのある形（ドーム）**：側面が斜めの層（`taper_mm`）や、高さごとの縮み方を決めた層（`profile`）。
- **丸い台（紙皿など）**：長方形の 4 隅の代わりに、縁の点から丸い台の向きと大きさを求めます（`top.circle`）。
- **立っている紙の部品**：横から撮った写真の輪郭を切り抜いて、薄い板として立てます（`cards`。頭・しっぽ・旗など）。
- **斜め上から撮った写真**：カメラの位置を写真から求め、高さのある所（層の上面・側面・部品）が写真のどこに写っているかを計算して貼ります。台の全体が写っていれば、真上でなくてかまいません。

## 形が合わないとき

この道具に合わない部分があっても、作るのをやめません。
1. 一番近い作り方で作り、どこを近似したか（例：丸い甲羅を、上がすぼまった層で表した）を報告します。
2. それでも表せない部分は、`solidglb.py` の関数（`Top`・`prism`・`loft`・`lathe`・`Glb` など）を import して、足りない部分だけを書きます。
3. どちらで作ったか、仮定した値は何かを、必ず伝えます。

## 準備（初回だけ）

```sh
cd tools/solid-glb
npm install            # three と gltf-validator（描画と検証に使う）
python3 -c "import cv2, numpy, mapbox_earcut"   # 無ければ pip install numpy opencv-python-headless mapbox_earcut
```

描画には Playwright と Chromium を使います（`require('playwright')` が動く環境が必要）。

## 手順

画像を見るのは、**写真を 1 回ずつ、格子を重ねた上からの写真を 1 回、`photo_overlay.jpg` を 1 回、`compare.jpg` を 1 回** が目安です。

1. **写真を見て、向きを決める。** どの辺が正面（手前）か、どの写真がどの向きかを決めます。正面は、使う人が向かう側です。上からの写真は斜め上からでもかまいませんが、**台（一番下の物）の全体** が写っている必要があります。
2. **上からの写真に格子を重ねて、位置を読む。**
   ```sh
   python3 tools/solid-glb/solidglb.py grid 上.png top_grid.jpg
   python3 tools/solid-glb/solidglb.py grid 上.png part.jpg 0.5 0.2 1.0 0.6    # 一部を拡大（x0 y0 x1 y1）
   ```
   位置はすべて「写真の幅・高さに対する割合」（x は右、y は下）で読みます。コマンドはリポジトリの一番上から書いています。
3. **設定ファイルを書く。** 下の例を写して直します。置き場所は写真と同じフォルダが楽です（写真の場所は設定ファイルからの相対パス）。
4. **作る。**
   ```sh
   python3 tools/solid-glb/solidglb.py build 設定.json --out out
   ```
   出てきた数字（大きさ、カメラの見下ろす角度 `camera.elevation_deg`、丸い台の当てはまり `circle_fit.rms_mm`、部品の数、`features_not_snapped`）を読み、`out/photo_overlay.jpg` を 1 回見ます。元の写真にモデルを重ねた画像で、黄色が基準の長方形（丸い台なら、それを囲む正方形）、緑が層の輪郭（細い線が下の縁、太い線が上の縁）、赤が丸い部品、赤紫が立てた紙の部品の足元です。線が写真の縁に乗っていなければ、設定を直して作り直します。`top_overlay.jpg` は、まっすぐに直した写真に輪郭を重ねたものです（共通の `outline` があるとき、緑の線）。
   斜め上からの写真で気をつけること：
   - 斜め上からの写真では、高い層の「カメラから遠い側」の下の縁は、見えている輪郭より内側にあります（上の方が奥へずれて写るため）。`photo_overlay.jpg` で、一番外側の線が写真の物の輪郭からはみ出していないことを確かめ、はみ出していたらその側の点を内側へ寄せます。はみ出した部分には背景の色が貼られます。
   - カメラからほとんど見えない向きの側面は、写真ではなく `material` の色になります。`material` の色は写真の色に近づけておきます。
   - 丸い台をほぼ真上から撮ったときや、紙皿が反っているときは、傾きの向きがずれやすくなります。`photo_overlay.jpg` の黄色い四角が台を囲んでいること、`circle_fit.rms_mm` が小さいこと（数 mm 以内）を確かめます。
5. **確かめる。**
   ```sh
   python3 tools/solid-glb/solidglb.py check out
   ```
   検証のエラーが 0 件であることを確かめ、`out/compare.jpg` を 1 回見ます（1 組ごとに、左が写真、右がモデル）。
6. `out/model.glb` と `out/compare.jpg` を渡します。仮定した値（大きさ、層の高さ、近似した所）を一言添えます。

### `top`
上からの写真と、その写真のどこが基準の面かです。基準の面は、`plane` の層の **上面** です（省くと一番上の層）。台の上面の 4 隅や縁は、この面の上にあります。
- `corners`：基準の面を囲む長方形の 4 隅。**奥の左、奥の右、手前の右、手前の左** の順（正面に立って見たときの左右）。写真の中で物が回っていてもかまいません。この順番で向きが決まります。順番が裏返しだと、作るときに注意が出ます（`report.json` の `corner_order_mirrored`）。
  - 角が丸い・欠けている物は、まっすぐな辺を延ばして交わる点を書きます。写真の外に出てもかまいません（0 より小さい、1 より大きい値を書ける）。
- `circle`：丸い台（紙皿など）のときは、`corners` の代わりに書きます。`rim` は台の上面の縁の点（5 点以上。ぐるりと散らばるように。欠けや切り込みの所は避ける）、`front` は台の中心から見て正面の側にある点（台の上ならどこでもよい）。縁の点から台の向きと距離を求め、台を囲む正方形を `corners` の代わりに使います。当てはまりは `report.json` の `circle_fit`（`rms_mm` が 1〜2 mm より大きければ、縁の点を見直す）。
- `width_mm`：左右の幅（奥の左から奥の右まで）の実寸。丸い台では直径（奥行きも同じ）。分からなければ仮定して、仮定したことを報告します。
- `depth_mm`：奥行きの実寸。省くと、写真の遠近から計算します（`report.json` の `depth_from_photo`）。正面からまっすぐ斜めに撮った写真（台形に写る）では計算できず、4 隅の辺の長さの比になるので、分かれば書きます。
- `focal_px`：写真の焦点距離（ピクセル）。省くと、4 隅の遠近から求め、求められなければ写真の長い辺の 0.75 倍とします（`report.json` の `focal_px`・`focal_source`）。斜めの写真で高い物がずれるときに直します。
- `plane`：基準の面にする層の名前。
- `erase`：写真から消したい所（手、影など）を囲む多角形のリスト。基準の面の上の点で書きます。まっすぐに直した写真で、まわりの色で埋めます。

`report.json` の `camera` は、求めたカメラの位置（見下ろす角度 `elevation_deg`、基準の面の中心からの距離 `distance_mm`）です。実際の撮り方と大きく違うときは、4 隅・縁の点・`width_mm` を見直します。

### `outline`
共通の輪郭です。基準の面の上で、写真の上で一周なぞった点です（始点と向きは自由）。へこみや面取りも点で書きます。自分の輪郭（`layers[].outline`）を持たない層は、これを使います。すべての層が自分の輪郭を持つときは省けます。
- 背景が写り込まないよう、**線は縁の少し内側**に置きます。外側にずれると、上面の端に背景の色が帯のように出ます。
- `outline_round_mm`：角を丸める半径。

### `layers`
下から上の順です。
- `height_mm`：層の高さ。横からの写真で、分かっている寸法（幅、ボタン、端子など）と比べて決めます。
- `base_mm`：層の底の高さ（省くと、ひとつ前の層の上）。
- `outline`：この層だけの輪郭（写真の割合の点）。`outline_at` が `top`（既定）なら層の上の縁、`bottom` なら下の縁をなぞった点として、その高さで写真から読み替えます。見えている方の縁をなぞります（斜めの写真では、ふつう上の縁）。
- `outline_round_mm`：この層の輪郭の角を丸める半径（既定 0）。
- `inset_mm`：輪郭を内側に縮めます（負の値で外側）。
- `taper_mm`：**上がすぼまった形**。上の縁が、下の縁より全周でこの長さだけ内側になります（側面が斜め）。なぞった縁（`outline_at`）はそのままで、もう一方の縁を求めます。
- `profile`：**丸みのある形（ドーム）**。`[[高さ, 縮み], ...]` の並びで、高さは層の底から、縮みは下の縁からの内側への長さ（mm）。最初は `[0, 0]`、高さは増える順。例：`[[0, 0], [18, 5], [26, 12], [32, 26], [35, 45]]`。最後の高さが層の高さです（`height_mm` は省ける。両方書くときは同じ値）。`taper_mm: t` は `profile: [[0, 0], [height_mm, t]]` と同じです。`outline_at` が `top` ならなぞった輪郭は一番上の段、`bottom` なら一番下の段です。
- `"texture": "top"`：層の上面に上からの写真を貼ります。
- `"side_texture": "top"`：層の側面のうち、上からの写真のカメラの方を向いている所（面の向きとカメラへの向きの内積が 0.35 より大きい所）にも写真を貼ります（斜めの写真で、側面の色紙などを写すとき）。カメラからほとんど見えない側面・向いていない側面と底は `material` の色です。
- 隠れている所：写真で、後の層・丸い部品・立てた紙の部品の陰になって見えない所は、写真の代わりに `material` の色で塗ります（その層だけの写真を作る）。塗る範囲は、陰の形を `hidden_margin_mm`（設定ファイルの一番上に書く）（既定 1 mm）だけ広げた範囲です。手作りの物は実物がモデルより数 mm 大きいことが多く、上の物の色が下の層にはみ出して写るので、そのときは 3〜5 mm などに増やします。
- `material`：側面と底の色（0〜1 の RGB）、`roughness`、`metallic`。

`report.json` の `layers` には、層ごとの高さ・点の数（`points`、斜めの層は `ring_points`・`rings`）・`taper_mm`（`profile` では一番上の縮み）・`own_texture`（隠れている所を塗った写真か）があります。

### `features`
上面に載る丸い部品です。同じ大きさの物を 1 組にまとめ、`at` に中心を並べます。
- `shape`：`button`（縁と押す面のあるボタン）、`dome`（丸い粒）、`disc`（平たい円柱。ねじの頭など）。
- `diameter_mm`、`height_mm`：外側の直径と高さ。直径は、格子で読んだ幅 ×（`width_mm` ÷ 上面の幅）で見積もります。
- `on`：載せる層の名前（省くと一番上の層）。`at` はその層の上面の高さで写真から読み替えます。
- `"texture": "top"`：部品にも上からの写真の色を貼ります。透明・半透明の部品や、模様のある部品に向きます。付けなければ `material` の色です。
- 位置は自動で直ります：作るときに、まっすぐに直した写真から円を探し、近い円（`snap_tolerance_mm`、既定 4 mm 以内）の中心へ動かします。見つからなかった組は `features_not_snapped` に出ます。止めたい組には `"snap": false` を書きます。基準の面の上にない組（`on` が別の高さの層）は動かしません。
- 部品ごとの結果は `report.json` の `feature_list` にあります（最後の位置。`x_mm` は左の辺から、`z_mm` は奥の辺からの距離。`moved_mm` は動かした距離）。2.5 mm より大きく動いた部品は、作るときに一覧が出ます。別の円に合ってしまうことがあるので、`top_overlay.jpg` で確かめます。

### `cards`
立っている紙の部品（頭、しっぽ、旗など）です。横から撮った写真の輪郭を切り抜き、薄い板として立てます。
- `photo`：その部品を正面から撮った写真。`outline`：その写真の上で、部品の縁の少し内側をなぞった点。
- `height_mm`：輪郭を囲む長方形の実際の高さ（または `width_mm` で幅）。写真の遠近は直しません。
- `foot`：その写真で、下の `at` の位置に立つ点（省くと、輪郭を囲む長方形の下の辺の真ん中）。
- `at`：足元の位置。上からの写真の上の点で書きます。`on` の層（省くと `top.plane` の層）の上面の高さで読み替えます。`lift_mm` で上下にずらせます。
- `photo_right`：部品の写真の右が、物のどちらを向くか。`front`（+Z）、`back`（−Z）、`right`（+X）、`left`（−X）。正面を向いて立つ頭なら `right`（正面から見て写真がそのまま見える）。
- `thickness_mm`：厚み（既定 0.5）。横から見た細い紙の帯なら、その帯の幅を書きます。
- `texture`：既定は `true` で、両面に部品の写真を貼ります（裏も同じ絵）。`false` なら `material` の色です。`material` は縁の色です。

`report.json` の `cards` に、部品ごとの大きさ・厚み・足元の位置（mm）が出ます。

### `side_marks`
側面の小さな暗い四角（端子の口、スイッチの穴など）です。`layer` の壁の `side`（`front`・`back`・`left`・`right`）に付けます。`along_frac` は辺に沿った位置（0〜1）、`height_frac` は層の中の高さ（0〜1）です。

### `views`
見比べる向きです。`photo` を書くと、その写真の右にモデルを並べます。
- `az`：正面（0）から、右側（90）、奥（180）、左側（270）へ回る角度。`el`：見下ろす角度。`zoom`：大きく写す倍率。斜めの上からの写真は、`camera.elevation_deg` を `el` に書くと見比べやすくなります。
- 真上の写真（`el` 89.9）では、`up` に「写真の上が、物のどちら側か」を書きます。奥なら `[0, 0, -1]`、手前なら `[0, 0, 1]`、右なら `[1, 0, 0]`、左なら `[-1, 0, 0]`。

## できないこと

実物で確かめたのは 2 つだけです：上が平らな操作盤（写真 5 枚）と、紙皿の工作（斜め上・横の写真 2 枚。丸い台、丸みのある層、立てた紙の部品、隠れている所の色）。ほかは合成した画像のテストだけです。

- 丸いかたまり（球、粘土の動物など）は作りません。層を積んだ形で近似するか、上の「形が合わないとき」のとおりにします。
- 斜めの層（`taper_mm`・`profile`）は、輪郭がおおむね凸の形に向きます。深いへこみのある輪郭を大きく縮めると、側面が折れ曲がることがあります。縮めた側の角は丸くなりません（とがったまま）が、広げた側の角は丸くなります。
- 部品は丸い物と、立てた平らな紙だけです。四角いボタンやレバー、丸い側面の部品は作りません。
- 立てた紙の部品の写真は、遠近を直しません。正面から撮った写真を使います。
- 上からの写真に写っていない面（奥の側面、底、隠れている所）は `material` の色です。底の細かい形は作りません。
- 斜めの写真の位置合わせは、カメラの焦点距離に頼ります。求められないとき（正面からまっすぐ斜めに撮った写真など）は仮定の値なので、高い所の写真が少しずれることがあります（`focal_px` で直せる）。
- 実寸は写真からは分かりません。`width_mm` は測るか、仮定します。
- 透明な素材は不透明な色で表します。
